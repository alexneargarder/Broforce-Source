# Broforce-Source

`decompile.py` decompiles a Broforce install's `Assembly-CSharp.dll` with a pinned ilspycmd into `Source/`: the C# tree, `Assembly-CSharp.csproj`, `Directory.Build.props`, `BUILD.md` and the IL listing `Assembly-CSharp.il`. Everything under `Source/` is generated and gitignored except the folder `AGENTS.md` files.

## The generated tree
- Never edit, add or move a file under `Source/` other than an `AGENTS.md`: change `decompile.py` or `layout-map.txt` and rerun.
- A `Source/` with no `.cs` files has not been generated; README's Usage section has the command.
- The folder docs describe the reference build, MVID `4952e11f-34bd-45eb-9d34-a304cfbdda7b`. `Source/BUILD.md` records the source DLL's SHA256 and MVID, whether it is the reference build, and whether Broforce-Docs' entries were inlined as `///` comments. Every other comment is ilspycmd's; the game's code carries none of its own.
- Global-namespace types sit in the top-level folders `layout-map.txt` names, placed by its rules, or in `Unsorted/` when no rule matches; `Properties/` holds the assembly attributes. Every other top-level folder is a namespace as ilspycmd writes it, its subfolders the sub-namespaces. A mapped folder and a namespace folder of similar name or subject are separate: `Net/` is global and `Networking/` is namespace `Networking`, and so with `Util/` and `Utility/`, `Fx/` and `Effects/`, `Perks/` and `Rogueforce/`.
- A file holds one top-level type with its nested types; every generic arity of a type shares one file named without an arity suffix.
- Grep for a member and read a line range around it; the largest classes are too long to read whole.
- `dotnet build` in `Source/` reports exactly three errors, the `get_delegates` getters in `Rewired/Platforms/Switch/NintendoSwitchInputManager.cs`, which the pinned ilspycmd leaves as error comments. Any other error is new.
- An RPC with an argument whose class a mod declares, a mod's bro included, runs on no client, the sender's own included, because the RPC serializer, `TypeSerializer` (`Net/`), covers only a fixed list of the game's types (`cached_SerializeMethods`) unless a mod extends it or patches `SerializeObjectWithType`. Until then the game's own RPCs that pass the bro never run for a mod's bro, among them spawn placement, the deathmatch HUD, spike-trap impaling, the helicopter exit, flex-power pickups, and a networked shot's or grenade's setup RPC, which passes it as `FiredBy`.

## IL
A method's IL in `Source/Assembly-CSharp.il` ends at the line `} // end of method <Type>::<Method>` and starts at the `.method` line above it. The end marker is indented, so a search for it must not be anchored at line start. The `.method` header runs over several lines, with the method's name and signature on a later line (`instance void Update () cil managed`), so find a method by its end marker, not by its header. When the patch point is a call or field access, grep for its operand, `<type>::<member>` with the type that declares the member, namespace and outer type included (`Networking.Networking::RPC`): a call to a virtual method names its first declaration (`Unit::Damage`) whichever override runs, and only `base.` calls name an override. The first end marker below a match names the method it is in. `<Type>` is the type's own name, without namespace or outer type; a generic type keeps its arity (``AssetBundleReference`1``), and compiler-generated names are single-quoted (`'<UpdateComponent>c__AnonStorey0'`). Accessors are `get_<Name>` and `set_<Name>`, constructors `.ctor` and static constructors `.cctor`. A marker matches once for each overload in each type of that name, and types in different namespaces or outer types can share a name, compiler-generated iterators most often: the nearest unindented `.class` line above a match names its top-level type with its namespace. A coroutine's code is in the `MoveNext` of the nested iterator type that the coroutine method's IL creates with `newobj`.

## Folder docs
Folder docs are not loaded at session start. Open one before tracing code when its line below names the behaviour the task is about; a class the task mentions, or an RPC or spawn the trace passes through, is not by itself a reason:
- `Source/Units/AGENTS.md` — `TestVanDammeAnim`, the base of every bro and `Mook` (`Enemies/`), so a change to it reaches enemies too: the actor chain, the frame loop, input from `Player` (`Players/`) and `InputReader` (`Input/`), the AI input that overwrites it for non-heroes, animation, movement, primary fire into `ProjectileController` (`Projectiles/`), specials, the melee button's checks before `StartMelee`, melee cancelling, and the helicopter exit that calls `GameModeController.LevelFinish` (`GameFlow/`).
- `Source/Bros/AGENTS.md` — what makes a character player-controlled and the player characters that are not a `BroBase`, the melee-type dispatch, where a melee type's move is implemented, and which shot spawns give each client its own copy and which belong on the owner only.
- `Source/Players/AGENTS.md` — hero spawning: the `RespawnBro` round trip through the host and `ChangeBro`, then `SpawnHero` through `Networking.InstantiateBuffered` (`Networking/`), `SetUpHero` and spawn placement on the map.
- `Source/GameFlow/AGENTS.md` — `GameState` across scene loads and the `Map` (`Level/`) statics its `Apply` overwrites on every load, block persistence among them, and the level end: `LevelFinish`, the `LevelSuccess` or `LevelFail` trigger `TriggerManager` (`Triggers/`) fires when the win timer runs out, the outcome and `LevelOverScreen`, and `SwitchLevel` loading the next scene under a new session ID.
- `Source/Networking/AGENTS.md` — the `Networking` hub: sending an RPC through `RPCController` (`Net/`) and `RPCBatcher` (`Net/`), the drop until a peer's sync handshake, and networked instantiation through `InstantiationController` (`Core/`) and `Registry` (`Core/`).
- `Source/Net/AGENTS.md` — receiving an RPC: `RPCController`'s queue and its hold while a level loads, the silent drops in `Execute`, the `RPCSecurity` (`Networking/`) check and the refusal it logs, which argument types serialize, and how a static RPC's class resolves in a mod's assembly.
- `Source/Core/AGENTS.md` — `Registry`: component numbering, registering objects created outside networked instantiation, and how deterministic IDs are allocated and when they match across machines.
- `Source/Projectiles/AGENTS.md` — `ProjectileController`'s local and networked spawns, the networked ones through `Networking.Instantiate` (`Networking/`), and the grenade seed that sets the fuse.
