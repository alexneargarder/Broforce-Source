# Projectiles

- `ProjectileController.SpawnProjectileLocally` is a plain `Object.Instantiate` plus `Fire`: the projectile is registered nowhere, so no RPC reaches it. Called on every client, it gives one copy on each client.
- `ProjectileController.SpawnProjectileOverNetwork` and `SpawnGrenadeOverNetwork` instantiate with `Networking.Instantiate` (`Networking/`) (not buffered, so late joiners never receive them), then send their setup RPCs to all. They dereference the result, so a prefab outside `InstantiationController.PrefabList` (`Core/`) throws `NullReferenceException` there. Each client that calls one spawns its own networked copy: call them on the owner only (`IsMine`).
- Their setup RPC (`Fire` for a projectile, `SetupGrenade` for a grenade) passes `FiredBy` as an argument. A `FiredBy` whose class a mod declares isn't serialized, since the RPC serializer covers only a fixed list of the game's types, so that RPC fails on every client, the caller's own included; a bro class a mod declares gets one shot per client only by calling the `…Locally` variants from code every client runs.
- A `SpawnGrenadeLocally` call that runs on every client needs a seed every client computes alike, not a `Random` draw. One reached only on the owner, as a prefix on `SpawnGrenadeOverNetwork` is when its caller checks `IsMine` (the base `TestVanDammeAnim.UseSpecial` (`Units/`) and `BroBase.ThrowAirstrikeGrenade` (`Bros/`) do), spawns a grenade on the owner alone, and `Random.Range(0, 10000)` is the seed the networked path draws. The seed sets the fuse: `SetupGrenade` seeds the grenade's `Randomf` (`Util/`), and `Shrapnel.Launch` (`Fx/`) sets `life` from it, so a `ReduceLife(lifeM)` must come after `Launch`. `SpawnGrenadeLocally` calls `Launch` itself and takes no `lifeM`, so call `ReduceLife` on the grenade it returns.
