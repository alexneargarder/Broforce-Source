# Units

The actor chain is `NetworkObject` (`Net/`) → `BroforceObject` (`Core/`) → `NetworkedUnit` → `Unit` → `TestVanDammeAnim`. `TestVanDammeAnim` is the base of every bro and every `Mook` (`Enemies/`), so a change to it reaches those enemies too: code meant only for players checks `IsHero` or `playerNum >= 0`.

## Frame loop
In a normal frame, `TestVanDammeAnim.Update` runs, in order: `CheckInput`, the animation tick, `CalculateMovement`, `RunMovement`, `RunGun`, `CheckFacingDirection`, `RunFiring`.
- `t` is the unit's own delta: `SetDeltaTime` clamps `Time.deltaTime` to 0.0334 s, and a high-five or time-bro boost replaces it with a scaled delta clamped to 0.04 s. Use `t`, not `Time.deltaTime`, for unit timers.
- Input, for a hero with `playerNum` 0–3: on the owning client `CheckInput` reads `HeroController.players[playerNum].GetInput` (`Players/`), which reads `InputReader` (`Input/`), or `BotBrain` (`Players/`) for a bot. On every other client it calls `RunSync()`, and the buttons arrive through the `[Syncronize]` (`Net/`) property `InputBits`. Every client then simulates every bro from that input: the special and melee presses `CheckInput` detects, and primary fire, run on all clients.
- After that branch, `CheckInput` calls the virtual `GetEnemyMovement()` on every unit matching `(playerNum < 0 || playerNum > 3 || IsEvil() || (!isHero && !isZombie)) && health > 0`; `MookGeneral` (`Enemies/`) and `Satan` (`Enemies/`) override `IsEvil()` to return true. The base version overwrites the input from the unit's `enemyAI` (a `PolymorphicAI` (`Enemies/`)) or else its `EnemyAI` (`Enemies/`) component, and leaves it alone on a unit with neither; `Mook`, other enemy classes and `Citizen` override it. `Mook`'s gib and kill-report code, and per-frame code in subclasses such as `ScoutMook` (`Enemies/`), dereference `enemyAI` without a null check, so clearing it can throw there.

## Animation
- The frame advances in `Update`: `counter += t`; when `counter > frameRate` it calls `IncreaseFrame()` then `ChangeFrame()`. `frameRate` is seconds per frame, and most `Animate*` methods reassign it on each frame change, so a value set in `Awake` is lost.
- `ChangeFrame` chooses the `Animate*` method from `actionState` plus the `usingSpecial`, `doingMelee`, `WallDrag`, `wallClimbing`... flags.
- A frame is a cell of the sprite sheet: `sprite.SetLowerLeftPixel(column * spritePixelWidth, row * spritePixelHeight)`, columns counted from 0 at the left and rows from 1 at the top (the y argument is the cell's bottom edge, measured down from the sheet's top).
- Running with `useNewFrames` plays 8 frames from `AnimateActualNewRunningFrames` at `runningFrameRate`. Movement speed is `speed`, which the animation does not read.

## Movement
- `CalculateMovement`: input to velocity, jumps, wall jumps, air jumps, and `wallClimbing` while jump is held on a wall.
- `RunMovement`: per-state movement, then `ConstrainToCeiling`, `ConstrainToWalls`, `ConstrainToFloor`. Wall drag (`WallDrag`) and ledge grapple are decided inside `ConstrainToWalls`. The climb's upward kicks come from `AnimateWallClimb`, which sets `yI` on fixed frames, so climb speed follows the animation.
- Variable jump height: `CalculateMovement` keeps `yI = jumpForce` while `jumpTime > 0`; only the `Jumping` branch of `RunMovement` counts `jumpTime` down, and it zeroes it when jump is released. While an earlier branch runs instead (ladder, `doingMelee`, hanging, air dash), `jumpTime` is not counted down.
- On a unit with a `parachute`, the `IsParachuteActive` setter also writes `maxFallSpeed`: -50 when it opens, `originalMaxFallSpeed` when it closes.

## Helicopter exit
The helicopter exit is detected by the bro, not by `Helicopter` (`Vehicles/`): `RunMovement` calls `IsOverFinish` unless the unit is dead, and it acts only on the owning client. There an enabled, non-heavy unit with `playerNum` 0–4 overlapping the victory layer (for example a helicopter's or a `HeroLevelExitPortal`'s (`Level/`) collider) is made invulnerable and disabled, attached to the `Helicopter` on the collider's parent if there is one, and then `GameModeController.LevelFinish(LevelResult.Success)` (`GameFlow/`) is called, `isOnHelicopter` is set and `playerNum` becomes 5. When the collider's parent carries a `HelicopterFake` (`Vehicles/`), or a `Helicopter` on a map with `onlyTriggersCanWinLevel`, the bro is attached and the method returns before `LevelFinish` and those two fields.
- Other clients learn of the bro's own exit only through the `TargetAll` RPCs `IsOverFinish` sends for it, which also run at once on the owner. At a helicopter, `HeroController.AttachHeroToHelicopter` attaches and disables the bro, sets `isOnHelicopter` and calls the virtual `AttachToHeli`; at a portal, `SuckIntoPortal` spins the bro into it and stops its syncing, but leaves it enabled.
- `AttachHeroToHelicopter` takes the bro as an argument, which `TypeSerializer` (`Net/`) can't serialize for a class a mod declares, so for such a bro the call fails on every client, the owner's included: only `IsOverFinish`'s own attach on the owner happens, `AttachToHeli` never runs, and at a `HelicopterFake`, or any helicopter on a map with `onlyTriggersCanWinLevel`, `isOnHelicopter` is never set. On the owner the bro is disabled at every exit, a `HeroLevelExitPortal` (what a Hell level's final checkpoint opens) included, by the time `base.Update()` returns in the frame `IsOverFinish` fires, and only a helicopter reparents it to its `ladderHolder`; other clients get none of the attach, the disable or `Helicopter.Leave` unless the mod sends an RPC of its own whose arguments the serializer handles.

## Fire, special, melee
- Primary fire is a timer, not a button press: the press calls `StartFiring` from `CalculateMovement`, which primes `fireCounter` (the first shot comes in the same frame when `fireRate` is below 0.3 s), then `RunFiring` calls `UseFire` every `fireRate` while `fire` is held and `fireDelay` has run out.
- The base `UseFire` → `FireWeapon` → `SpawnPrimaryProjectile` → `ProjectileController.SpawnProjectileLocally` (`Projectiles/`) runs on every client: the base path never network-spawns a primary shot, and each client fires its own copy from the synced input.
- A special press calls `PressSpecial`, or `StartPockettedSpecial` when pocketed special ammo must be used. The base `PressSpecial` sets `usingSpecial` and `frame = 0` unless the unit is acid-covered or in a melee, and the base `AnimateSpecial` calls `UseSpecial` on a fixed frame.
- A melee press calls `PressHighFiveMelee`, which does nothing while the unit is dead or `MustIgnoreHighFiveMeleePress` holds. Otherwise it takes the first of: a nearby `TeleportDoor` (`Doodads/`); a grenade in reach, thrown back; a citizen to high-five, or a high-five for a press held past 1.5 s; a usable `Switch` (`Doodads/`); an enemy in reach or a cage to bust, with `StartMelee`; another player to high-five; else `StartMelee`. Deathmatch and Bro Down add a step after the door: a usable switch, or else `StartMelee` for each other unit in reach, players' included. The grenade step follows, and throwing one back cancels that melee; otherwise a melee under way ends the press in Deathmatch, and in Bro Down the list goes on. A bro that overrides it without calling the base loses door and switch use.
- `CancelMelee` is the restore hook for anything a melee changes. The `TestVanDammeAnim` version returns at once unless `doingMelee`, so put restores in an override, before or after the base call. A melee can also end without it: code that clears `doingMelee` directly, in `TestVanDammeAnim` and in some bros, skips `CancelMelee`.
