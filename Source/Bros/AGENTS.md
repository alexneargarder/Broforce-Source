# Bros

`BroBase.Awake` sets `isHero`, the protected `NetworkedUnit` (`Units/`) field behind `IsHero`, which `TestVanDammeAnim.CheckInput` (`Units/`) requires, with `playerNum` 0–3, to read the player's controller. Not every character a player controls is a `BroBase`: in Suicide Horde every player but the bro player plays `SuicideBro`, which derives from `TestVanDammeAnim` directly, and `TankBroTank` is a `Mook` (`Enemies/`).

## Melee
`BroBase.StartMelee` copies `meleeType` into `currentMeleeType` on every melee, forcing `MeleeType.Knife` while the bro stands on an `Animal` (`Units/`). `StartMelee`, `AnimateMelee` and `RunMelee` switch on `currentMeleeType`: `Knife` goes to the knife methods, `Punch` and `JetpackPunch` to the punch methods, and every other type to `StartCustomMelee`, `AnimateCustomMelee` and `RunCustomMeleeMovement` (except that `RunMelee` sends `JetpackPunch` to `RunJetPackPunchMovement` and `ThrowingKnife` to `RunPunchMovement`). `BroBase`'s `AnimateCustomMelee` and `RunCustomMeleeMovement` fall back to the knife, so a melee type does nothing of its own until a bro class overrides those hooks; a type's move lives in the bro class that overrides them. To give a bro class a melee of its own, set `meleeType = MeleeType.Custom` and override `StartCustomMelee` and the other two hooks, keeping the base `PressHighFiveMelee` or calling it from an override; the game's own bros use the named types.

## Networked shots
Every client runs a bro's `UseFire`, `UseSpecial` and melee from the synced input. The base `UseFire` calls `FireWeapon` with no ownership check; `Brommando`, `TankBro` and some other bros override `UseFire` to call it only when `IsMine`. A shot spawned from `FireWeapon` with `ProjectileController.SpawnProjectileLocally` (`Projectiles/`) and no `IsMine` check, as the base `SpawnPrimaryProjectile` does, is spawned by each client as its own local copy: one per client by design, not a duplication bug. An `IsMine` check belongs on the `…OverNetwork` calls only. `SpawnProjectileOverNetwork` and `SpawnGrenadeOverNetwork` give one copy only when nothing but the owning client reaches them, and they fail for a bro class a mod declares, because their setup RPC passes the bro as an argument the RPC serializer cannot send. The base `UseSpecial` throws `specialGrenade` with `SpawnGrenadeOverNetwork` on the owner only, so for a bro class a mod declares its `SetupGrenade` RPC fails the same way.
